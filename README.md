# Два генератора кодов на Python

Flask + Gunicorn, два отдельных процесса/контейнера:

| Сервис | Адрес после деплоя | Поведение |
| --- | --- | --- |
| Открытый | `http://SERVER_IP:8001` | Генерация при каждом открытии/обновлении |
| С авторизацией | `http://SERVER_IP:8002` | Код только после верного логина и пароля; F5 возвращает форму входа |

`SERVER_IP` нужно заменить публичным IP своего сервера. Это шаблоны адресов, а не уже опубликованные сервисы.

## Деплой на Ubuntu/Debian через Docker

1. Установи Docker Engine и плагин Compose по инструкции для своей ОС:
   https://docs.docker.com/engine/install/
   Проверь: `docker compose version`. Если пользователь не имеет доступа к Docker, выполняй команды Docker через `sudo`.
2. Загрузи папку проекта на сервер, например через SFTP в `/opt/code-services`. `.venv`, `.git` и `__pycache__` переносить не нужно.
3. Выполни на сервере:

```bash
cd /opt/code-services
cp .env.example .env
nano .env
```

Укажи свой логин и длинный случайный пароль вместо `CHANGE_ME`. Для паролей со спецсимволами используй одинарные кавычки в `.env`:

```dotenv
APP_USERNAME=demo
APP_PASSWORD='your-unique-random-password'
```

```bash
chmod 600 .env
docker compose up -d --build
docker compose ps
docker compose logs --tail=50
```

4. Разреши входящий TCP-трафик на порты **8001 и 8002** в firewall/security group панели хостинга. Проверь, что эти порты свободны. Порты Docker публикуются на всех интерфейсах; не полагайся только на UFW для ограничения доступа к контейнерам.
5. Открой оба адреса из таблицы в браузере. Во втором используй данные из `.env`. Для тестового создай отдельный пароль: обычный HTTP передаёт его без шифрования. Для постоянного публичного использования подключи домен и HTTPS через обратный прокси.

После перезагрузки сервера контейнеры поднимутся автоматически, если запущена служба Docker. Управление:

```bash
# Логи
docker compose logs -f
# После изменения кода или .env
docker compose up -d --build
# Остановка
docker compose down
```

Другие порты задаются слева в `compose.yaml`: например, `9001:8000` и `9002:8000`.

## Запуск на Linux без Docker

Python 3.10+; для Ubuntu/Debian при необходимости установи `python3-venv`.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
gunicorn --bind 0.0.0.0:8001 --workers 2 public_app:app
```

Во втором терминале из папки проекта:

```bash
. .venv/bin/activate
export APP_USERNAME=demo
read -rsp 'Password: ' APP_PASSWORD
export APP_PASSWORD
gunicorn --bind 0.0.0.0:8002 --workers 2 'auth_app:create_app()'
```

Этот вариант работает, пока запущены процессы; для постоянной работы проще использовать Compose выше. Файл `.env` автоматически читает только Compose, сами Python-приложения читают переменные окружения.

## Что происходит в коде

- `public_app.py`: GET `/` вызывает `secrets.randbelow(9000) + 1000` и рендерит страницу.
- `auth_app.py`: GET `/` всегда возвращает форму; POST `/login` проверяет учётные данные на сервере и только затем генерирует код.
- `static/auth.js`: отправляет логин через `fetch`, показывает код только в памяти страницы. Пароль после успешного входа стирается из формы. Cookies, localStorage и сохраняемой серверной сессии нет: авторизация действует на один запрос выдачи кода. При F5 браузер делает GET `/` и снова показывает форму. Это намеренная реализация требования «после обновления — выход».
- Ответы помечены `Cache-Control: no-store`.
- Код — число от 1000 до 9999. Каждый раз происходит новая независимая генерация; совпадения возможны с вероятностью 1/9000. Гарантия отсутствия повторов — отдельное требование.
- Один пользователь задаётся через окружение. Регистрация и база данных для этого тестового не нужны. Ограничение попыток входа не реализовано; это минимальное тестовое, а не полноценная система аккаунтов.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Ручная проверка: обнови первый сервис несколько раз; во втором проверь неверный пароль, верный пароль, F5, затем повторный вход. F5 должен сразу показывать форму без запроса повторной отправки POST.

Для сдачи отправь два реальных URL из таблицы после запуска и файлы `public_app.py`, `auth_app.py` (либо весь проект).

Документация: [Gunicorn с Flask](https://flask.palletsprojects.com/en/stable/deploying/gunicorn/), [переменные Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/).
